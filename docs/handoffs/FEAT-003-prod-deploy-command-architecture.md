# Architecture: Reusable SSH Production Deployment Command

## Existing Patterns Observed
- The bundle is a Symfony 7+/8+ `AbstractBundle`; configuration is declared in `LexioAdminBundle::configure()` and container parameters/services are wired in `loadExtension()` and `config/services.yaml`. There is no separate Extension or Configuration class to introduce.
- Bundle services use YAML autowiring/autoconfiguration with explicit definitions for configuration-bound services and explicit `console.command` tags for commands. Bundle service registration must remain configuration-driven; service-registration attributes are not appropriate here.
- The translation synchronization feature already uses an immutable options object (`TranslationSynchronizationOptions`), custom context exceptions, Contract interfaces, scalar bundle parameters, and a thin command that delegates work to a service.
- Existing bundle commands use `SymfonyStyle`, return `Command::SUCCESS`/`Command::FAILURE`, and have `CommandTester` unit tests. The deployment command should follow this pattern while preserving both stdout and stderr streaming from the remote process.
- The bundle has no existing SSH, deployment, or process-execution abstraction. The closest reusable boundary is the translation synchronizer plus its options object and public Contract interface.
- `D:\laragon\www\lexio-admin` is the starter application in scope. It already requires `symfony/process`, contains `scripts/dev_next_deploy.sh`, uses `config/packages/lexio_admin.yaml`, and stores application documentation under `docs/Documentation/`.
- `D:\laragon\www\exlege5\src\Command\ProdDeployCommand.php` is reference-only. Its hardcoded SSH constants, application namespace, TTY choice, and lack of quoting/validation must not be copied into the bundle, and `exlege5` must not be modified.

## Technical Design

### Components
- `composer.json` dependency: add `symfony/process` as a direct runtime dependency with the bundle's supported Symfony constraint (`^7.2 || ^8.0`). The host application's transitive dependency is not sufficient for a reusable bundle contract.
- `LexioAdminBundle::configure()` deployment tree: add an opt-in `deployment` section with `enabled`, `host`, `user`, `port`, `remote_path`, `deploy_script`, `identity_file`, and nullable `timeout`. Use host-agnostic defaults: `enabled: false`, `host: null`, `user: null`, `port: 22`, `remote_path: null`, `deploy_script: scripts/dev_next_deploy.sh`, `identity_file: null`, and `timeout: null`.
- Configuration processing and parameters: map deployment values to namespaced parameters such as `lexio_admin.deployment.enabled` and `lexio_admin.deployment.remote_path`, then inject them into the options service. Do not reuse `DEPLOYED_APP_URL`, translation Basic Auth values, translation timeout, `SITE_BASE_URL`, or the local translation directory; those settings have different semantics.
- `Service\Deployment\DeploymentOptions`: final immutable typed options object containing the eight deployment values. It is configuration data only; it must not read the container, environment variables, private-key contents, or the filesystem during construction.
- `Service\Deployment\DeploymentConfigurationValidator`: validate at command execution time so environment-backed values can produce a normal command failure instead of preventing the host container from booting. Validate non-blank host/user/path values, port range `1..65535`, positive finite timeout, optional identity-file path, control characters, leading-option values, and forbidden `.`/`..` path segments. Preserve spaces inside valid paths. When deployment is disabled, fail before identity-file or SSH checks and never create a process.
- `Service\Deployment\SshCommandBuilder`: a pure command-construction boundary. Return a `list<string>` for Symfony Process: `ssh`, optional `-p`/port, optional `-i`/identity path, `user@host`, and one remote command argument. The remote operation remains `cd <remote_path> && git pull && bash <deploy_script>` semantically, with each configured path represented as a separately single-quoted shell path value. Quote embedded single quotes safely; reject NUL/control characters and path traversal segments. The builder must never concatenate an unvalidated configured value into an executable fragment.
- `Service\Deployment\ProcessRunnerInterface` and `Service\Deployment\SymfonyProcessRunner`: isolate the Symfony Process dependency. The adapter receives the command array, output callback, and nullable timeout; it explicitly calls `setTimeout(null)` for the reference no-time-limit behavior or sets the finite timeout, runs with a callback for both stdout and stderr, and returns a typed process result. It must translate start/timeout failures into deployment-specific exceptions without dumping the command or any identity-file content.
- `Service\Deployment\SshDeploymentRunner`: orchestrate validation, command construction, and process execution. It should not contain Console formatting. A non-zero SSH/remote status is a failed deployment; the remote `&&` chain itself guarantees that the script is not attempted when `git pull` fails. No retries, rollback, migrations, branch selection, or automatic remediation belong here.
- `Contract\Deployment\DeploymentRunnerInterface` and `Contract\Deployment\DeploymentResult`: the narrow public seam used by the command and by host/test replacements. The result carries success, normalized exit status, and timeout state; streamed output is deliberately not accumulated in the result. Keep process-specific classes internal and expose only the minimal bundle contract.
- `Command\ProdDeployCommand`: register the command as `prod:deploy` even when deployment is disabled, so an operator receives actionable configuration guidance rather than a missing-command error. Keep it thin: create `SymfonyStyle`, print translated lifecycle messages, pass a callback to the runner that streams remote stdout/stderr, translate configuration/execution failures, and return Symfony command constants. Do not print the generated command, identity-file contents, or a password.
- Translation messages: command/configuration-facing strings must be semantic translation keys in the bundle's existing English and Bulgarian catalogues. Raw remote stdout/stderr is operational output and is streamed unchanged. Configuration and execution exceptions should carry translatable messages or stable keys; translation must happen at the Console boundary.
- Host guide deliverable: create `D:\laragon\www\lexio-admin\docs\Documentation\Deployment.md`. Document prerequisites, local SSH binary/agent/key setup, remote Git authentication, normal host-key verification, environment-safe `lexio_admin.deployment` configuration, identity-file configuration without key material, invocation, output/exit-code behavior, timeout, and troubleshooting. Explain that `exlege5` was only the behavioral reference and is not part of setup. The guide must use `.env.local` or the Symfony secrets mechanism for machine-specific values and must not add credentials to committed `.env` files.

### Implementation Order
1. **Configuration and dependency** — Add direct `symfony/process` dependency; add the `deployment` config tree, defaults, scalar parameters, typed configuration comments, and generated/reference configuration coverage if the repository maintains one. First normalize the conflicting default values in the PM specification.
2. **Internal deployment value and validation services** — Add `DeploymentOptions`, `DeploymentConfigurationValidator`, deployment-specific translatable exceptions/results, and path/host validation rules. Keep construction side-effect-free and defer runtime checks until invocation.
3. **Process and SSH infrastructure** — Add the process runner interface/adapter and `SshCommandBuilder`. Wire the concrete adapter through an interface alias. Ensure Process receives an argument array, never a locally shell-expanded command string, and that no host-key bypass option is supplied.
4. **Public Contract and orchestration** — Add the narrow `DeploymentRunnerInterface`/`DeploymentResult` Contract, implement `SshDeploymentRunner`, and wire its options, validator, builder, and process runner through `config/services.yaml` with constructor injection.
5. **Console integration** — Add `ProdDeployCommand`, exclude it from broad bundle resource discovery, and register it explicitly with the `prod:deploy` tag/name. Use `SymfonyStyle`, translated bundle messages, live stdout/stderr forwarding, and stable success/failure exit codes.
6. **Bundle tests** — Add configuration tests, builder/quoting tests, validator tests, process-runner tests with deterministic substitutes, runner tests, and `CommandTester` success/failure/disabled/timeout/output tests. Add minimal container wiring assertions for the command, aliases, options, and parameters. No test may require a live SSH host.
7. **Starter documentation** — Add `D:\laragon\www\lexio-admin\docs\Documentation\Deployment.md` using the starter app's existing documentation location. Do not modify `D:\laragon\www\exlege5`.
8. **Quality verification** — From the bundle root, run `make ci` after implementation. Keep all quality/test execution behind Make targets; do not run raw Composer, PHPStan, PHPUnit, or vendor binaries as the implementation workflow.

### Interfaces / Contracts
- `Lexio\AdminBundle\Contract\Deployment\DeploymentRunnerInterface::deploy(callable $output): DeploymentResult` — executes the configured deployment and invokes the callback for each remote stdout/stderr buffer. The callback signature should be documented as receiving the Process output type and buffer; it must not expose a shell command or secret.
- `Lexio\AdminBundle\Contract\Deployment\DeploymentResult` — final readonly DTO with at least `successful`, `exitCode`, and `timedOut` state. A timed-out or locally failed execution is never successful and has a non-zero normalized exit status.
- `Lexio\AdminBundle\Service\Deployment\ProcessRunnerInterface::run(array $command, callable $output, ?int $timeout): ProcessResult` — internal test seam around Symfony Process. It accepts a list of already-separated local arguments and returns a typed result without exposing `Process` to the runner or command.
- `Lexio\AdminBundle\Service\Deployment\SshCommandBuilder::build(DeploymentOptions $options): array` — internal pure boundary returning the complete SSH argument list, including the single remote command argument.
- `Lexio\AdminBundle\Service\Deployment\DeploymentConfigurationValidator::validate(DeploymentOptions $options): void` — internal boundary that throws a deployment-specific configuration exception before any process is created.
- `Lexio\AdminBundle\Service\Deployment\SshDeploymentRunner` — implementation of the public runner Contract; dependencies are injected through its constructor and include the options object, validator, command builder, and process-runner interface.
- `Lexio\AdminBundle\Command\ProdDeployCommand` — Console boundary; it depends on `DeploymentRunnerInterface` and the translation service only. It must not depend directly on `Process`, `ContainerInterface`, `ParameterBagInterface`, or deployment scalar parameters.
- Service wiring contract: `DeploymentRunnerInterface` aliases to `SshDeploymentRunner`; `ProcessRunnerInterface` aliases to `SymfonyProcessRunner`; `DeploymentOptions` receives only namespaced bundle parameters; `ProdDeployCommand` receives an explicit `console.command` tag with `prod:deploy`.
- SSH command contract: process arguments keep `ssh` options separate, include `-i` only when an identity path is configured, use `user@host` as one destination argument, and pass the complete `cd`/`git pull`/`bash` sequence as one remote-command argument. No password argument, shell wrapper, host-key bypass, automatic known-hosts file, or private-key content is permitted.

## Risks and Trade-offs
- **Host-specific deployment defaults:** Deployment is disabled by default and host/user/remote path remain `null` until configured. This avoids silently carrying values from the `exlege5` reference project into another host application.
- **Disabled command versus disabled registration:** Registering `prod:deploy` unconditionally satisfies the requirement for a non-zero, actionable response when disabled. The operation itself remains opt-in and performs no validation that could connect or no process creation when disabled.
- **Runtime versus container-time validation:** Config-tree type/range validation catches ordinary static mistakes, while the options validator catches empty/env-backed/path values at invocation. This avoids making every host boot fail merely because deployment is disabled or an optional identity path is absent.
- **Remote shell is unavoidable for the requested workflow:** SSH passes one remote command string to the user's remote shell. Single-quote path values, reject control/traversal/leading-option values, and keep `git pull`/`bash`/`&&` fixed so configuration cannot add a second command. Test the exact generated string with shell-significant fixture values.
- **Host-key verification remains delegated to OpenSSH:** The command must not add `StrictHostKeyChecking=no`, `/dev/null` known-hosts settings, or trust-on-first-use logic. The first host-key interaction may therefore require operator setup outside the command, which is intentional and must be documented.
- **TTY behavior differs from the reference:** Do not force a pseudo-TTY automatically. Symfony Process callback streaming works in interactive terminals and CI, while automatic TTY allocation complicates CommandTester/non-interactive execution. The remote deployment script is non-interactive by contract; operators should configure SSH/agent access before invoking the command.
- **No concurrent-run lock:** Deployment changes remote state and would normally justify a lock under the Console Commands rule, but the approved scope explicitly says concurrent invocations must be surfaced to the remote process without automatic coordination and excludes lock orchestration. Document this operational risk; do not add `symfony/lock` unless the specification changes.
- **Identity-file path versus key material:** Passing an identity path via a separate Process argument supports paths with spaces and avoids exposing contents. The guide must state that the path is local to the machine running `bin/console`, must be readable, and must be kept outside committed configuration when machine-specific.
- **Remote output may contain application data:** Stream it for operator visibility as required, but never echo the generated SSH command or append sensitive environment/config values. The bundle does not add password authentication, key generation, log persistence, retry, rollback, or redaction of arbitrary remote script output.
- **Starter-app documentation is a separate repository change:** The bundle implementation and its tests live in `lexio-admin-bundle`; `Deployment.md` belongs to `lexio-admin` and should be changed there only. `exlege5` remains read-only reference material.
